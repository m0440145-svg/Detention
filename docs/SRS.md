# نظام الإحسان: الاتصالات الإدارية داخل منصة المهام والقرارات

الإصدار 0.3.0 — 2026-10-08. يوسّع النظام الحالي بطلب المستخدم؛ لا يستبدل Snso للموارد البشرية والمشاريع والمالية. تفاصيل المواد النظامية ومحدودية انطباقها: [COMPLIANCE.md](COMPLIANCE.md).

## 1. النطاق ومعايير التشغيل

سجل IN/OUT/INT/CIR/DEC/RPL؛ استقبال يدوي وبريد وبوابة/API ومنصة حكومية؛ دورة من التسجيل إلى الأرشفة؛ ربط الإحالة بمهمة والرد بوارد. لا عقود أو محادثات شخصية. الكود والبيانات تحت ملكية الجمعية؛ PostgreSQL وملفات مشفرة قابلة للتصدير دون احتجاز لدى مورد.

العربية هي الافتراضية، مع اختيار الإنجليزية لشاشة الاتصالات والقوائم. تحفظ البيانات الأصلية بلغتها. هجري أم القرى وميلادي معاً، أرقام 0–9 وتوقيت Asia/Riyadh. العطلات وساعات العمل في MailSettings/Holiday.

أدوار النموذج الحالي تستمر دون حذف: admin/executive/assistant/head/employee/viewer/board. صلاحيات register/templates/compliance سمات إضافية. لا يُمنح admin حق اعتماد أو إغلاق أو الاطلاع التشغيلي.

**قبول A01:** تسجيل وارد، إحالة، فتح المراسلة؛ يظهر الخط الزمني والمرفقات والردود والإحالة/المهمة في ثلاث نقرات أو أقل. زمن أقل من ثلاث دقائق تسجيل+إحالة يتطلب اختبار خمسة مستخدمين فعليين؛ لم يُجرَ في هذه الجلسة.

## 2. القوالب والمستندات

ثمانية قوالب ابتدائية، دمج المتغيرات المسموحة، إصدارات مستقلة. الحقول الإلزامية للصادر كما BR01. محرر نص عبر textarea مع أدوات فقرة وعريض وعنوان وجدول؛ تعقيم خادمي بقائمة HTML محددة. الترويسة والاسم والترخيص والعنوان والتذييل في الإعدادات؛ خط Tajawal محلي مضمّن. PDF/A-3b ينشئه WeasyPrint محلياً؛ يمنع جلب شبكة أو ملفات غير الخطوط. تحقق مستقل veraPDF شرط قبول المستند الموقع من المزود؛ توليد PDF/A وحده ليس شهادة تحقق مستقلة.

**قبول A02:** قالب v1 لا يُعدّل؛ إضافة v2 لا تغيّر v1 أو رسائلها. HTML script/event handlers تُزال. صادرات PDF تحتوي XMP PDF/A وقراءة RTL. ملف المزود الذي لا يجتاز veraPDF لا يصدر.

## 3. Metadata والترقيم

Correspondence: UUID، رقم نهائي، معرف تاريخي، نوع، عنوان ≤250، محتوى/ملخص، رقم خارجي، تاريخ الأصل، جهة مرجعية، تصنيف، استبقاء، وحدة، مسؤول، مصرحون، نسخة، سرية، أولوية، حالة، قناة، منصة، استحقاق ومهلة الجهة، ساعات SLA، المشروع/البرنامج، كلمات مفتاحية، مؤشر بيانات شخصية، توقيع، إحالة أولى، إتمام وأرشفة. مرفق: اسم أصلي/نوع/حجم/SHA-256 ومسار خاص مشفر.

قيد Sequence فريد لكل نوع/سنة هجرية؛ تخصيص ذري ولا استرجاع للأرقام المستهلكة. IN عند التسجيل؛ OUT وبقية الأنواع رقم DRAFT حتى نهاية الاعتماد والتوقيع. حجز رقم ضمن طلب توقيع لا يعرضه كرقم صادر قبل اكتمال التحقق. الوارد المكرر جهة+رقم يمنع؛ موضوع متشابه ≥90% خلال 30 يوماً ينبه المستخدم للمراجعة.

**قبول A03:** طلبات متزامنة لا تنتج رقمين متماثلين؛ إلغاء لا يعيد رقماً؛ طرف غير مرجعي يرفض؛ استيراد IN-1448-000099 يرفع Sequence إلى ≥99. البيانات الشخصية في قائمة الموظفين تُحجب جزئياً؛ نص المستند يعرض فقط وفق الوصول المشروع.

## 4. سير العمل

الوارد: registered → referred → active → waiting/review/approval → done → archived، مع returned/cancelled. الانتظار الخارجي يوقف SLA بمبرر؛ resumed يحتسب الوقت الفعلي دون مدة الانتظار. الصادر: draft → review → approval (n مستويات) → signing → issued → sent → received → archived. رفض بسبب → returned. لا يسمح تغيير الحالة بـPATCH عام.

تصنيف يوجه للوحدة؛ جهة إشرافية توجه للتنفيذي+الامتثال بشرط الوصول للمحمي. إحالة instruction إلزامية وmode parallel/sequential؛ الوضع المتسلسل لا ينفذ المرحلة التالية قبل السابقة. التحويل إلى Task مرة واحدة؛ إغلاق المهمة المعتمدة يكمل الإحالة. التفويض بمدة ودور مخول، يظهر النائب في التدقيق. matrix مرجع معتمد من المجلس، وليس القيم التجريبية.

**قبول A04:** تجاوز مستوى اعتماد/اعتماد المعد لنفسه/اعتماد مسؤول النظام يرفض. إغلاق قبل إتمام إحالات التنفيذ يرفض؛ الاستثناء التنفيذي المسبب يتطلب تسجيل الفروع المستثناة. رفض يحفظ كل القيم قبل/بعد ومقارنة النص. الرد يتطلب IN مرتبطاً مصرحاً.

## 5. الأمان والخصوصية

الوصول يجمع الدور والوحدة والمسؤول والمصرحين والإحالات. المحمي restricted/secret وصول مباشر فقط؛ مسؤول النظام لا يرى المحتوى. البحث والتصدير والتقرير يعيدان تطبيق الوصول. التنزيل/الطباعة للمحمي ممنوع افتراضياً؛ إذن التنفيذي باسم مستخدم، بحد أقصى سبعة أيام، تدقيق كامل وعلامة مائية.

MFA إلزامي في الإنتاج: TOTP مشفر، منع إعادة الرمز، خمس محاولات ثم حظر 15 دقيقة. API والواجهة يخضعان للشرط. جلسة خمول 30 دقيقة قابلة للضبط، إدارة IP اختيارية، TLS عبر Caddy، AES-256-GCM للمرفقات ونسخ الطوارئ. تشفير قرص PostgreSQL يتطلب ضبطاً مثبتاً لدى المستضيف السعودي؛ ليس خاصية تثبتها migration. ClamAV مطلوب عند الرفع في الإنتاج؛ غياب الفحص يرفض الملف.

MailEvent append-only بقيود ORM ومحفزات DB، يتضمن actor/IP/old/new/hash chain. logs/API لا يسجل كلمات مرور أو رموز أو محتوى رد المزود. سجل ProcessingActivity وطلبات صاحب البيانات ذات أجل 30 يوماً واستجابة موثقة. الإتلاف لا يتجاوز السند القانوني للحفظ والتدقيق والنسخ الاحتياطية.

**قبول A05:** مستخدم غير مخول يحصل 404/403 دون عنوان؛ MFA replay يفشل؛ عبث ciphertext يفشل؛ توقف مكافحة البرمجيات الضارة يفشل مغلقاً؛ DELETE/UPDATE MailEvent بSQL يرفض؛ فصل وظيفي admin مثبت بالاختبارات. مراجعة أدوار ربع سنوية عبر التقرير المجدول؛ HR termination يسحب جلسة الوصول ويلغي رموز OAuth.

## 6. التوقيع والتحقق

سياسة لكل نوع تحدد methods وموقّعين وبصمات شهاداتهم بالترتيب. INT/CIR يمكن إثبات داخلي وفق السياسة؛ OUT/DEC/RPL لا يستخدم ذلك. مسار PAdES: طلب مرتبط بتجزئة المحتوى والمرفقات وPDF؛ outbox إلى المزود؛ callback HMAC وطابع ≤5 دقائق؛ تحقق جذور ثقة مرخصة، صلاحية وإلغاء الشهادة، الطابع الزمني، سلامة الملف الأصلي، ترتيب وبصمات الموقّعين وPDF/A. أي نتيجة ناقصة ترفض، ولا يصدر رقم نهائي.

QR يشير لـ/verify/UUID، يظهر المرجع والتاريخ والجهة والموقّع والصلاحية دون المحتوى. لا يعرض بيانات المحمي. إعادة إصدار بقرار التنفيذي تُبطل التوقيع وتعيد الاعتماد وتحفظ الرقم المستهلك والنسخة السابقة. لا تُدّعى نفاذ أو شهادة مرخصة من توقيع داخلي أو TOTP محلي؛ نفاذ يحتاج خدمة وهوية مصرح بها.

**قبول A06:** PDF غير موقع أو من مزود غير موثوق/شهادة غير معينة أو نتيجة لمحتوى تغير يفشل. callback مكرر لنفس الملف idempotent، ملف مختلف يرفض. التحقق العام لا يكشف الموضوع/المرفقات. لا يوجد توقيع إنتاج مرخص مُنفذ دون حساب مزود.

## 7. الاستبقاء وOCR والبحث

سياسة قانونية معتمدة لكل تصنيف، مدة أو حفظ دائم. قيم demo غير معتمدة. انتهاء المدة → RetentionCase؛ عضوين مستقلين على الأقل عن مقدم الترشيح من اللجنة النشطة؛ حجز قانوني يمنع التنفيذ؛ محضر لازم. الحفظ الدائم يمحو تاريخ انتهاء الحفظ دون حذف سجل. الإتلاف المادي للمرفقات يحتاج إثبات موصل الأرشيف بإتلاف النسخ الاحتياطية قبل الإجراء، ويحفظ المرجع وبصمات ومحضر وتدقيق دون حذف Correspondence.

Tesseract ara+eng محلياً، كل الصفحات حتى حد مضبوط افتراضه 100؛ تجاوزه يرفض بدلاً من إسقاط صفحات صامتاً. page confidence مع تنبيه <70%، اقتراح رقم/تاريخ/موضوع/جهة/ملخص لا يعتمد تلقائياً. تطبيع الهمزة والياء والتاء المربوطة والتشكيل، بحث في المحتوى وOCR، فلاتر Metadata وسجل البحث باسم المستخدم. thread بالوارد والردود والقرارات والإحالات والمرفقات.

**قبول A07:** حجز أو لجنة ناقصة يمنع؛ تاريخ حفظ غير منتهٍ يمنع؛ ملف خارج مجلد الترحيل/بصمة غير مطابقة يرفض؛ OCR عربي غير مثبت يفشل صراحة؛ نتيجة اقتراح لا تعدل Metadata دون المستخدم. البحث لا يوسع الصلاحية.

## 8. SLA والإشعارات

critical:2 ساعة للإحالة/1 يوم للإنجاز، urgent:8 ساعة/3 أيام، important:8/5، normal:16/10. ساعات عمل 9–17، جمعة/سبت والعطلات المعتمدة، قابلة للضبط. مهلة أقصر من الجهة تتقدم. أخضر <70%، أصفر 70–100، أحمر تجاوز. 80% تذكير،100% مدير،150% تنفيذي؛ dedup حسب الموعد والمستلم. لا تصعيد للسجل النهائي أو الانتظار المبرر.

MailAlert داخل النظام؛ preferences email/digest/critical_sms؛ Delivery يعيد المحاولة تدريجياً إلى ثماني محاولات مع lease وIdempotency-Key. البريد/SMS غير المهيأ لا يرسل فعلياً. لا ترسل عناوين المحمي في قنوات خارجية.

**قبول A08:** تقويم الجمعة/السبت والعطلات مثبت؛ تكرار scheduler لا يكرر التنبيه؛ تغيير الموعد يسمح بتذكير جديد مرتبط به؛ pause/resume لا يحتسب وقت الانتظار. موصل تجريبي HTTP503 يصير retry دون ادعاء التسليم.

## 9. التكامل

OAuth2 مع authorization code وPKCE وread/write scopes، حد 300 طلب/ساعة، سجل استدعاء، Session وCSRF للمتصفح. HR يومي عبر poll وفوري عبر callback موقع، مع معرفات مصدر ثابتة؛ انتهاء الخدمة يعطل الحساب والرموز، ولا يؤدي غياب موظف من دفعة إلى حذف ضمني. يتوقف الإدخال اليدوي عند تفعيل المصدر.

Microsoft Graph للإرسال، وموصل موقع لاستقبال M365/Exchange. DMS وSMS والتوقيع وSnso بعقد gateway موثق، يحتاج مطابقة عقد المورد الفعلي. OIDC للمؤسسة وAD؛ يمكن ربط SAML عبر broker موثوق إلى OIDC. نفاذ يحتاج خدمة وحساب مزود معتمد. Webhooks التسجيل والإحالة والتأخر والإغلاق لا تتضمن محتوى، وتستبعد المحمي.

**قبول A09:** نطاق OAuth لا يتجاوز الدور، إنهاء HR يبطل الرموز، تكرار حدث صحيح لا يكرر المعاملة، تغيير المحتوى أو توقيع/وقت غير صالح يرفض. لا ادعاء اتصال حي دون بيانات الربط.

## 10. المؤشرات والتقارير

نسبة SLA = المكتملة قبل الموعد ÷ المكتملة ×100، هدف 90%. متوسط الإحالة الأولى والإنجاز بساعات عمل، فئات التأخر 0–3/4–7/8–15/>15 يوماً، حجم الشهر حسب النوع والجهة والتصنيف، التزام الجهات الإشرافية، دورات الاعتماد والرفض. غياب البيانات يظهر «—».

السجل الرسمي، المتأخرات الأسبوعية، أداء الوحدات الشهري، مرشحو الاستبقاء، مراجعة الصلاحيات، الاطلاع على المحمي. Excel يعطل تفسير المدخلات كصيغ، وPDF/A محلي، وجدولة تعيد تقييم صلاحية المستلم. لا مرفقات محمية في البريد.

**قبول A10:** لا أرقام خارج نطاق الوحدة، لا إرسال لحساب معطل، نص Excel يبدأ = لا ينفذ كصيغة، غياب المقام ليس نسبة صفر.

## 11. الاستخدام

أربع لوحات: الموظف وإجراءاته، السكرتارية والقيد والإحالة، مدير الوحدة والاعتماد، التنفيذي وSLA. صفحة المراسلة تجمع البيانات والمرفقات والإحالات والمهام والأسباب والتدقيق، وتربط صفحة التوقيع والاستبقاء والنسخ. جداول الهاتف ببيانات مسماة وتمرير، تركيز واضح وبديل للحركة. Alt+N تسجيل وAlt+S بحث. الإجراءات POST وCSRF.

**قبول A11:** فحص HTML والاختبارات الآلية، ثم اختبار WCAG2.1AA بقارئ شاشة، واختبار مرئي على جوال بعروض 360/390/768px، وخمسة مستخدمين بقياس زمن التسجيل والإحالة. هذه الاختبارات الميدانية لم تحدث في الجلسة.

## 12. التشغيل

SQLite للتطوير فقط؛ PostgreSQL16 للإنتاج مع Docker وgunicorn وCaddy وscheduler مستقل. أسرار البيئة منفصلة، مرفقات خاصة، إصدارات اعتماد مثبتة، CI يفحص الهجرات والاختبارات. backup يومي مشفر؛ إعداد pgBackRest كامل يومياً وزيادة كل ساعة وWAL كل خمس دقائق، يحتاج تركيب خادم DB ومخزن سعودي. تمرين ربع سنوي يثبت RPO≤1h وRTO≤4h.

**قبول A12:** فحص نشر وCI PostgreSQL وscheduler، حمل إنتاج يثبت p95<2s، اختبار اختراق قبل الإطلاق وسنوياً، إثبات سعودي لقاعدة البيانات والملفات والتدقيق والنسخ. ملف إعداد وحده ليس نتيجة تشغيل.

## 13. الترحيل والإطلاق

JSON صادر رسمي من Snso، يطابق معرفاً تاريخياً ورقماً أصلياً وتواريخ ووحدة وجهة ومسؤولاً وتصنيفاً ومصرحين ومرفقات ومساراتها وبصماتها. dry-run افتراضي، commit صريح، حفظ الأرقام ورفع Sequence، التوقيع التاريخي legacy_unverified إلى أن يتحقق مستقلاً. مطابقة عدد السجلات والملفات والأرقام قبل التحويل.

المراحل: 0 اعتماد الصلاحيات والحفظ والاستضافة؛ 1 MVP وHR وترحيل تجريبي وتشغيل متوازٍ؛ 2 SLA وتقارير وبريد؛ 3 توقيع وQR وOCR واستبقاء؛ 4 تحليلات وAPI. مدة التشغيل المتوازي اقتراح يحتاج اعتماد الجمعية، مع مسؤول واضح للدفعة ومحضر مطابقة وخطة رجوع.

**قبول A13:** dry-run لا يغير DB أو ملفات، duplicate/checksum يرفض، original IDs والمرجع محفوظان، تقرير مقارنة قبل/بعد وخطة rollback. لا ملفات Snso تاريخية فعلية قدمت في الجلسة.
