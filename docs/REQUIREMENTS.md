# تغطية المتطلبات المرفقة

| المتطلب | التنفيذ |
|---|---|
| هوية إحسان RTL، تجاوب، خط عربي، بلا صور أشخاص | قوالب core + CSS، Tajawal محلي، صفحات دخول ولوحات وإدارة |
| الدخول بالبريد/الجوال وكلمة مرور، أدوار سبعة | User، EmailPhoneBackend، policy، LoginAttempt، CSRF وجلسات |
| وحدات وموظف متعدد الوحدات ودليل الموظفين | User.units، Unit.head، نماذج الإدارة |
| جميع حقول المهمة وإسناد فردي ومتعدد ووحدات | Task، participants وparticipating_units وassignment_mode، مسؤول إلزامي |
| فرعيات واحتساب تلقائي ومرفقات | Subtask، save_subtask، مرفقات مرتبطة بالفرعية |
| حالات وانتقالات وتحديثات وتاريخ | Status، TRANSITIONS، Update، Audit؛ التأخر والتعثر مؤشرات مستقلة |
| عدّاد الاستحقاق | مخفي للمغلقة والملغاة، «تستحق اليوم» للصفر، «متأخرة X يوم» للتأخير ويشمل انتظار الاعتماد |
| فصل مسؤول النظام | المستخدمون والوحدات والإعدادات فقط، دون تنفيذ أو اعتماد أو إغلاق عبر HTML أو API |
| تسجيل عائق وطلب تدخل ورد ومعالجة | Obstacle، report_obstacle، resolve_obstacle، تعليقات timeline |
| قواعد وتذكير وتصعيد أسرع للحرجة | RuleSettings، flags، run_rules، scheduler، التفرد |
| مركز متابعة مستقل حسب الخطر | أربع مجموعات رئيسية متداخلة، مع فلاتر وتذكير وتصعيد جماعي ذري ضمن الصلاحيات |
| دور المجلس / أمين المجلس | قراءة القرارات والنسب الكلية وتقارير تنفيذها، دون تعديل المهام أو القرارات |
| أسباب إلزامية واتساق الحالة والنسبة | سبب التعثر والتمديد والإعادة، وتحقق خادمي وقيد قاعدة بيانات لسير 100% والاعتماد |
| ردود وتعليقات متفرعة وإشارات وملفات | Comment.parent، mentions، mentioned_units، Attachment |
| سجل تدقيق لكل مهمة وقرار | Audit مرتبط بالمهمة أو القرار؛ المستخدم والوقت والسبب وقيم قبل/بعد، ومحفزات PostgreSQL/SQLite تمنع التعديل والحذف |
| Notification Center وأحداث التكليف والتعليق والعائق والاعتماد | Notification، notify، عرض وتمييز القراءة |
| الموظف/الرئيس/التنفيذي ولوحات حسب النطاق | dashboard وpolicy، مؤشرات وجداول ورسوم وتدخلات وملخص تأخير |
| قرارات واجتماعات وقرار إلى مهام متعددة | Meeting، Decision، Task.decision، نماذج وتحويل API |
| حقول حوكمة القرار | جهة مصدرة، رقم محضر ومرفق محمي، تاريخ استحقاق وحالات القرار الخمس |
| نسب تنفيذ واعتماد القرارات | عمودان في القائمة وملخص في التفاصيل؛ كلية للإدارة التنفيذية وضمن نطاق القراءة لبقية المستخدمين |
| 100%، طلب اعتماد، إعادة، إغلاق | update_progress، change_status، منع الاعتماد الذاتي والعائق المفتوح |
| 12 تقريرًا ومؤشرات وفلاتر | reports، report_rows، kpis، بحث وصف/موظف/قرار/اجتماع/رقم |
| Excel وCSV وPDF وطباعة | تصدير خادمي Excel/CSV، طباعة المتصفح وحفظ PDF |
| حماية الملفات، تشفير كلمات المرور، HTTPS، الجلسات، معدلات، نسخ | Django password hash، validate_upload، download، Caddy، LoginAttempt، script backup |
| PostgreSQL وفهارس وعلاقات | 7 ترحيلات، قيود المفاتيح والتفرد والنسبة والتواريخ، Docker وCI |
| بيانات عربية: 15 موظفًا و30 مهمة وقرارات وتعليقات وتنبيهات | seed_demo: 20 حسابًا، 16 وحدة، 30 مهمة، 3 قرارات |
| اختبار الصلاحيات وسير الإغلاق وتحويل قرار | core/tests.py، قبول عبر API وصفحات الخادم |
| البريد وWhatsApp وOTP لاحقًا | نقاط توسع موثقة؛ لا إرسال خارجي مفعّل |
| ربط التوقيع والتقويم وDrive والموارد البشرية مستقبلًا | API وخطة التوسع، يحتاج اعتماد خدمات ونطاقات واتفاق حقول قبل التشغيل |

قاعدة البيانات تستعمل جداول auth القياسية للأدوار والصلاحيات المساعدة، M2M للإسناد والوحدات، وAudit موحد لتاريخ الحالات والنشاط، وحقول المستخدم لبيانات الموظف. لذلك لا تطابق أسماء الجداول المقترحة حرفيًا، مع حفظ الوظائف والعلاقات الأساسية.

النظام لا ينشئ تصنيف "أكثر الموظفين التزامًا" من عدد الإنجازات وحده؛ تقرير الموظفين يتيح مقارنة الإنجاز والتأخير، والالتزام يعتمد موعد التسليم. المقارنة الإدارية تحتاج مراعاة تعقيد التكليفات ولا ينبغي استخدام عدد المهام كمقياس منفرد.
